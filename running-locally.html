Running Emage locally

Start the storage API, load the WebAssembly codecs, and run the same image experiments as the project article.

Hosted client

The client is published independently at GitHub Pages. The repository workflow compiles the public Emage-Wasm source and publishes static files only. Enter your separate API address in the Server URL field. For a remote API use HTTPS; localhost points to the visitor’s own machine. The server’s rebuild console is not part of Pages.

The blog can connect to a separate demo proxy through its Demo proxy URL field. The server must allow the client origin https://autovizz.github.io, without the project path. Repository variables EMAGE_API_URL and EMAGE_DEMO_URL can set default service addresses.

Requirements

The workspace contains three sibling repositories: Emage, Emage-Server, and Emage-Wasm. The API can run through Docker Compose. The client is served as static files; the article's throttling proxy uses Python's standard library. Asset generation and the client checks use Node.js 22 or later.

The static client serves all four codec artifacts under wasm/. Its Docker image compiles them from the Emage-Wasm checkout. For plain static hosting, build EmageWasm to populate the client’s wasm/ directory.

Start the storage API

In Emage-Server, configure a nonempty EMAGE_UPLOAD_PASSWORD in the local .env file, then start the service:

cd Emage-Server
docker compose up --build -d

The default API address is http://localhost:3233. Upload and delete requests use the configured password. Image reads do not use that password; the decryption key stays in the browser. An empty server upload password disables authenticated writes.

For a native run with .NET 10 installed, use make run in the server repository. Supply its upload password through the server configuration key Emage__UploadPassword; the Compose .env file is not automatically loaded by a native process.

Open the upload and download client

In another terminal, serve the client directory:

cd Emage
python3 -m http.server 3433

Open http://localhost:3433/. Enter the API address and the upload password, choose a source image, and encode it. Save the generated keys before uploading. The finest key is the master; each coarser key grants less detail. Use the image viewer with a saved key to read the stored file.

Serve the files over HTTP so ES modules and WASM load normally. Keys saved by the UI remain in this browser's local storage; the current connection and key also carry between workspace pages in the tab. The password is not saved. Local storage is a convenience for this demo, not a key backup.

Run the article's network experiments

The separate backend deployment includes the demo proxy on http://localhost:8082. Open the article, enter that address in Demo proxy URL, and click Connect. The client-only Docker stack does not include this proxy. Ports 3434–3437 serve the gallery’s four independent sample-image origins. The backend uses its upload password to seed the public fixtures. For Pages, set DEMO_PUBLIC_ORIGIN=https://autovizz.github.io; remote deployments also set four public HTTPS addresses in DEMO_TRANSPORT_ORIGINS.

With the API running, start the article server from the client repository:

cd Emage
npm run blog

Open http://localhost:8082/blog.html. This command builds or verifies ten distinct sample image pairs, seeds the reserved blog-demo/v1/ paths on the API, and starts the Python throttling proxy. It reads the upload password from the environment or the sibling server's .env file. It does not put that password in a browser asset.

The sample PNGs and keys are intentionally public. The owner/reader example demonstrates resolution grants using the real codec; these samples are not private images.

To choose another port or API address, use the already-generated assets directly:

python3 tools/demo_server.py --port 8085 --api http://localhost:3233

The proxy allocates four additional loopback ports for gallery transfers. It serves these documentation pages too. A plain static server can display the article, but its network experiments require the proxy. Use Stop experiment to cancel an active run before changing settings.

Troubleshooting

“Address already in use”

A process is already listening on that port. Use its existing server if it serves the right checkout, stop it in its terminal, or choose another port. For the plain client server use python3 -m http.server 8081; for the article use the --port example above. Restart an old article proxy after updating its Python code, then refresh the page.

HTTP 401 when uploading

The upload password field must match the password configured on the running API. A decryption key does not authenticate an upload. Check the API's configuration and restart or recreate the service after changing it. A blank 401 response body is valid; the client displays an explanation. The article proxy needs the same write password when seeding samples.

No codec or no experiments

Check the browser's network panel for missing JavaScript or WASM files. All four codec artifacts must come from a compatible build. If the article reports that independent gallery origins are missing, restart it using npm run blog rather than the plain static server.

A coarse image or a rejected key

A coarse key is expected to stop at its grant. Test with the master only if you are entitled to that detail. An unrelated key is rejected; changing the requested resolution does not grant access. See resolution keys and authenticated grants.

Run the checks

# In Emage, with codec artifacts present:
npm install
npm test

# Article, documentation links, and proxy checks only:
npm run test:blog

The client checks use jsdom, the real WASM codec, and in-process transport adapters. Proxy tests check byte pacing, shared budgets, cancellation, and allowlists. These checks do not replace a browser run against your API for rendering and live transport behavior. The experiment methodology explains the scope of these checks and what still needs live browser measurements.
