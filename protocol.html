From packet windows to decoded frames

A small preview becomes a sharper image as new detail arrives. Earlier parts of the image stay useful throughout the load.

One image, several resolutions

Think of an image as a small base view plus successive sets of detail. Emage numbers these levels from L0, the coarsest, to the full-resolution endpoint. A finer view needs the base information and every detail level up to its endpoint.

The article's samples start at 16×11 pixels. Each step doubles both dimensions, reaching 256×176 at L4 and 1024×704 at L6. The first preview is a real smaller image, enlarged into the viewing area while more detail arrives.

Try the level viewer to watch those steps.

Choose enough detail for the view

The browser starts by learning the image's dimensions and available levels. It then combines the display size with the reader's key grant to decide how much detail to request.

A 256-pixel thumbnail of a 1024-pixel image does not need the full-resolution endpoint. Likewise, a key granting only a small preview stays limited to that view even if the reader asks for the original. The key is checked locally and never sent to the storage server.

Download only the next detail

A progressive load requests the base view first. After decoding it, the browser asks for the next level and adds it to what it already holds. The next response contains new information, rather than another copy of the earlier preview.

A one-shot load can request the same final set of levels together. Both approaches need the same image information; progressive loading spends additional requests to get an earlier view on screen. A high-latency connection can make those extra requests more expensive.

Show the frame that has actually arrived

For each step, the browser combines the downloaded information, checks it, and decodes a new frame. The current-level indicator changes only after that frame is decoded. While the next level downloads, the earlier view remains visible.

This preserves the useful part of progressive loading: the reader can see a real image before the final view is ready, and a thumbnail can stop as soon as it has enough detail.

Inspect earlier views without downloading again

Once a level has arrived, its coarser views are already represented in the downloaded image. In the interactive viewer, clicking L0, L1, or another available level renders locally without a new request.

Loading a finer endpoint is an explicit action. Use Stop experiment to end a run before changing its settings or switching examples.

Keep storage separate from decryption

The server stores the prepared image and returns the requested resolution information. The browser holds the key and handles decryption and display. A storage server therefore does not need a reader's key to serve a preview.

Uploading and deleting use a separate server password. That password controls changes to stored files; it does not grant access to the encrypted image. See resolution keys for the access model.
