How to run Emage, how progressive delivery works, and how a key determines the detail a reader can reconstruct.

Emage project notes · 17 October 2026

Start with an image

Emage stores one JPEG 2000 codestream and serves windows of its spatial resolution pyramid. The browser can decode a coarse image before downloading the finer detail. Each resolution zone can also be encrypted under a different key, so a recipient's key sets the maximum resolution they can reconstruct.

The interactive project article puts those ideas next to working examples: three loading strategies, ten concurrent images, local inspection of downloaded levels, and owner/reader views of the same ciphertext. Start there to see the behavior, or follow the setup guide to run it yourself.

How the parts fit together

These articles describe the current repository. In this documentation, a “layer” means a spatial resolution level, with L0 the coarsest. It does not mean a JPEG 2000 quality layer. The encoder currently uses one quality layer.

The sender prepares an image, the server stores and delivers its parts, and the reader decrypts and displays the view its key permits. The storage server does not receive image keys.

The protocol article explains how a preview gains detail. The resolution-key article covers authentication and the limits of a grant. For commands and checks, use the local setup guide; for timing definitions and bandwidth calculations, see the experiment methodology.
